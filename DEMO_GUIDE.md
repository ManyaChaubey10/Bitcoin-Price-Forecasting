# Professor demonstration guide

## Start the local app

Use Python 3.12 and Node.js 20 or later. From the project root in PowerShell, create and activate `.venv312` (leaving `.venv` as-is) and install the locked dependencies once:

```powershell
if (-not (Test-Path .venv312)) { uv venv .venv312 --python 3.12 }
. .\.venv312\Scripts\Activate.ps1
uv sync --active --locked --all-extras
```

Terminal 1, start FastAPI:

```powershell
python -m uvicorn btc_forecasting.api.main:app --reload --app-dir src --port 8001
```

Terminal 2, start React:

```powershell
cd frontend
npm install
npm run dev
```

Open the local Vite address printed in Terminal 2. The API's interactive interface is at `http://127.0.0.1:8001/docs`.

The app reads the repository's saved data and model artifacts. It does not download data or train models at startup. If the saved bundles are missing in another checkout, the model cards will report that state; do not regenerate them over existing runs.

## Suggested talk track

1. **Data contract:** point out the date protocol shown in the sidebar: training through 2023, validation in 2024, final fit through 2025, and 2026 as the final untouched evaluation period.
2. **Market context:** show the actual price, volume, daily return, and trailing 30-day annualized volatility plots. Explain that these are historical descriptions, not future information passed to training.
3. **Router:** select one-day RMSE and Automatic. The existing 2024 registry shows ARIMA's RMSE point estimate is only slightly better than persistence and marks that gain as not established as reliable, so the router chooses persistence. Explain that this is intentionally conservative.
4. **Manual comparison:** choose each model in turn, or compare all four forecasts from the same current data origin. The card values are generated by loading the saved artifacts. The feature contract and model diagnostics appear in Explainability.
5. **Unvalidated horizon:** select 7, 14, or 30 days. The app will not automatically route because no saved 2024 validation record exists for those horizons. ARIMA and persistence may still generate forecasts; XGBoost/LSTM are marked unsupported beyond one day because future features are not available.
6. **Final evaluation:** show the saved 2026 actual-vs-predicted chart and metrics. State explicitly that these numbers are for reporting only and are not used by the router. The saved period currently ends November 14, 2026.
7. **Limitations:** highlight that feature ablation, multi-horizon validation, paired reliability analysis, and ensemble validation are still open research work. Existing XGBoost/LSTM artifacts share the current feature table, so the UI does not claim model-specific feature optimization.

## Evidence and files

- Validation routing evidence and artifact provenance: `configs/model_selection.json`.
- Date boundaries and final-fit cutoff: `configs/default.yaml`.
- Router policy: `src/btc_forecasting/selection.py`.
- API and inference integration: `src/btc_forecasting/api/`.
- Existing trained and evaluation artifacts: `artifacts/runs/<run-id>/` (ignored by Git).
- Current project boundaries and follow-up plan: `ARCHITECTURE.md`.

Avoid claiming that one model is best for a horizon unless its matching validation record supports that conclusion. Do not cite final 2026 evaluation results as a model-selection reason.
